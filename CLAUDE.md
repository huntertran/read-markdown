# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

VS Code extension ("Read Markdown", id `huntertran.read-markdown`): a reading-focused Markdown preview webview with heading outline, collapsible sections, selection→search highlight sync, two-way scroll sync, typography settings, Mermaid and highlight.js.

## Commands

```bash
npm run build          # esbuild: dist/extension.js + dist/media/main.js, copies mermaid.min.js to dist/media
npm run watch          # rebuild on change
npm run check-types    # tsc for ALL projects: root tsconfig (src, test), webview/tsconfig.json, test/webview/tsconfig.json
npm run lint           # eslint (flat config, type-aware via projectService); no-floating-promises/no-misused-promises are errors
npm test               # pretest builds + bundles tests into out/, then unit (mocha) + integration (VS Code host)
npm run test:unit      # mocha on out/test/unit + out/test/webview — requires `npm run pretest` first (tests are not run from TS)
npm run test:integration
npm run package        # vsce package -> .vsix
npm run demo:gifs      # re-record docs/images/*.gif (scripts/demo/record.mjs; one scene: `node scripts/demo/record.mjs edit`)
```

`scripts/demo/record.mjs` starts the `.vscode-test` VS Code with `--remote-debugging-port` and attaches with `playwright-core` (`_electron.launch` fails: release builds block `--inspect`). It strips `ELECTRON_RUN_AS_NODE` from env (set inside VS Code terminals). Frames come from the CDP screencast, the cursor is a drawn overlay, and ffmpeg encodes the GIF. Scenes use real selectors, so update them when renaming webview classes.

Single test: tests run from bundled JS, so rebuild first (`npm run pretest`), then
- unit: `npx mocha out/test/unit/renderer.test.js --grep "source lines"`
- integration: `npx vscode-test --grep "<pattern>"` (opens `test/fixtures` as workspace, see `.vscode-test.mjs`)

Webview modules are tested in Node on a jsdom window (DOMPurify does not work on happy-dom): `test/webview/*.test.ts` (own tsconfig with the DOM lib, excluded from the root tsconfig). Each file calls `useDom()` from `test/webview/dom.ts` in its top `describe`; it installs and removes the DOM globals, so host tests stay DOM-free. A module that imports `webview/api.ts` needs an `acquireVsCodeApi` stub first; keep import-time DOM work out of modules that tests load.

`typescript` in `package.json` is an npm alias of `@typescript/typescript6`, because typescript-eslint cannot load the TS 7 native package. `tsc` is TS 7 through the `@typescript/native` alias; `tsc6` is TS 6. Drop the alias once typescript-eslint supports TS 7. CI (`.github/workflows/ci.yml`) runs check-types, lint, tests under xvfb and `npm audit --omit=dev`.

Esbuild does no type checking — always run `npm run check-types`. `F5` launches an Extension Development Host on `test/fixtures` (good long sample: `test/fixtures/long-ai-doc.md`).

## Architecture

Two separate bundles that only talk via `postMessage`:

- **Extension host** (`src/`, Node, CJS, `vscode` external) — renders Markdown to HTML.
- **Webview** (`webview/`, browser IIFE, own tsconfig with DOM lib, no `vscode`/Node imports) — DOM work only.

`src/protocol.ts` is the shared contract (`ToWebview`, `FromWebview`, `UiConfig`, `QUICK_SETTING_KEYS`, `WebviewState`). It is included in both tsconfigs and must stay free of runtime imports. Adding a message or UI option means editing protocol + both sides.

### Extension side
- `extension.ts` registers commands, a `WebviewPanelSerializer` (restore after reload, keyed by `WebviewState.uri`), and a custom text editor `readMarkdown.editor`. Both panel kinds become a `PreviewPanel` (`kind: 'panel' | 'editor'`).
- `PreviewManager` is the singleton hub: panel registry by document URI, one shared markdown-it renderer, settings cache, `CustomCssProvider`, and all VS Code event listeners (text change → debounced render, selection → highlight, visible ranges → scroll, config change → broadcast config, auto-open). Also resolves link clicks: `openLink` is a thin call into `preview/linkOpener.ts` (`LinkOpener`: pure decisions with injected ports, no runtime `vscode` import, unit-tested for the confirm-before-stat order and the fragment decoding); it classifies through `preview/paths.ts` (pure: `resolveReference` classifies external http/https/mailto, ignored other schemes, fragments and local targets, and reports `inside` = within `allowedRoots`, the same roots as the webview `localResourceRoots`; `.md` targets open in a preview). A local target outside those roots is opened only after a modal confirmation, shown before any `stat`/open so a UNC path is not touched first.
- `PreviewPanel` owns one webview: CSP'd HTML shell from `preview/html.ts`, `localResourceRoots`, a file watcher for on-disk changes (agents rewriting the file), 250 ms render debounce. Nothing is posted until the webview sends `ready`; on `ready` it sends `config` then `render`, then initial scroll/highlight. The CSP (built by pure `preview/csp.ts`) has no remote `style-src`/`font-src`; `security.allowRemoteContent` gates `https:` in `img-src`/`media-src`, and changing it rebuilds every open panel's webview HTML (`reloadWebview`, then `ready` as above).
- `render/markdown.ts` — markdown-it (`html: true`) + footnote + task lists. A core rule stamps `data-line` (0-based source line) on every block-opening token and collects `blockLines`; this source map drives scroll sync and search occurrence targeting. Also: heading slugs (`render/headings.ts`, GitHub-style dedupe `-1`), front matter, GitHub alerts, highlight.js, Mermaid placeholders, and `resolveResource` rewriting relative image paths to webview URIs. Pure (no `vscode`) → unit-testable.
- `config/settings.ts` reads `readMarkdown.*` into `Settings`; `toUiConfig` projects the subset the webview needs. `validateQuickSetting` whitelists/validates every value coming from the webview quick panel before `updateSetting` writes it (to the most specific scope already defining it; `''` removes the key).
- `config/styles.ts` (pure) turns settings + theme presets into a `--rm-*` CSS-variable block consumed by `media/preview.css`. `config/customCss.ts` loads/watches user CSS files.
- `edit/` — in-preview block editing (opt-in `readMarkdown.edit.enabled`). Top-level blocks carry `data-line-end` (exclusive, from `token.map[1]`; front matter too). `blockText.ts` (pure) converts between the source range and the textarea text (EOL, trailing blank lines kept verbatim); `blockEdit.ts` does the version-checked `WorkspaceEdit`. Edit requests are validated against the last render first (`EditController.checkRendered`, pure checks in `edit/rendered.ts`): `requestBlockSource`/`editBlock` only for an exact non-HTML `topBlocks` range, `toggleTask` only for a line in `RenderResult.taskLines`, `moveListItem` only for the complete item list of one `RenderResult.lists` entry, and only if the cited `docVersion` is that of `lastRender` and of the live document (else `stale`; an unrendered range is `invalid`). Raw `html_block`/`html_inline` content goes through `render/rawHtml.ts`, which removes the attributes reserved for renderer output (`data-line`, `data-line-end`, `data-item-end`, `data-task`, `data-href`, `data-move-id`, `data-vscode-context`, `data-rm-*`) so author HTML cannot impersonate it. The renderer then stamps the first opening tag of an `html_block` (`stampRawHtmlBlock`, after neutralizing, never before) with `data-line`, `data-line-end` (top level) and the flag `data-rm-html`, so track changes can mark raw HTML; such blocks stay non-editable (host `isRenderedBlock`, webview `editBlock` and the `rmHtml` context key hide Edit) and blocks starting with a comment, closing tag, `script` or `style` stay unmarked. `edit/editController.ts` (`EditController`, built by `PreviewPanel` with a narrow `EditHost`: settings, live document, last render + version, post, render-after-edit) handles `requestBlockSource`/`editBlock`/`toggleTask`/`moveListItem`: it validates against the last render, applies the edit, renders immediately (`renderAfterEdit` clears `posted` so the render is always posted), and saves if `edit.saveOnCommit` or no tab shows the document. `PreviewPanel` only routes the messages.
- Track changes vs git index (`readMarkdown.changes.mode`: `inline`/`gutter`/`off`). VS Code's SCM-diff hooks for custom editors (`customEditorDiffs`, `textEditorDiffInformation`, `documentDiff`) are proposed API, so: `scm/gitBaseline.ts` reads the index version through the `vscode.git` extension API (`repo.show('', fsPath)`; non-blocking: returns undefined until the API is initialized, then fires `onDidChange`; per-URI cache refreshed on `repo.state.onDidChange`, fires only when the content changed; no runtime `vscode` import: the extension lookup and the emitter are injected, `scm/vscodeGit.ts` `createGitBaseline()` wires the real ones, so it is unit-tested against a fake Git API). `PreviewPanel.render` renders that original with the same renderer (cached) and sends `render.changes = { originalHtml, ops }`; `ops` = `diffDocument` over `RenderResult.topBlocks` (source text of each `data-line-end` block). `diff/` is pure and shared with the webview (in `webview/tsconfig.json` include): `textDiff.ts` (LCS `diffSequences`, `tokenize`/`tokenizeLines`, `diffTokens`, `similarity`, `tokenBag`/`bagSimilarity`), `blockDiff.ts` (`alignBlocks`: common prefix/suffix, then similarity-weighted alignment so one unchanged block can't strand edited ones, then same-kind modify pairs, then move detection among leftovers). SCM-tab clicks are deliberately left to VS Code's text diff (tab replacement was tried and dropped).
- `sync/selection.ts` (pure): selection text → search term (strips Markdown wrappers/line prefixes), plus `blockStartFor`/`countOccurrences` so the webview can highlight the *specific* occurrence, identified by block line + occurrence index.

### Webview side
`webview/main.ts` wires modules: `sanitize` (DOMPurify allowlist of tags, attributes and URL schemes, defence in depth on top of nonce CSP; keeps `<style>`, heading ids and the renderer's `data-*`), `sections` (wraps headings into collapsible `<section class="rm-section">`), `nav` (outline + filter + active heading), `scroll` (data-line ↔ scrollY map, anchor line kept across reflow), `search`, `codeblocks` (copy button posts `copy` to host), `mermaid` (lazy-loads `dist/media/mermaid.min.js`; `mermaid.theme` + `mermaid.look`, paired themes mapped to their dark variant by scheme (`DARK_VARIANT`); `auto` = Mermaid `base` with `themeVariables` resolved from `--rm-*` through a hidden probe element and `color.ts` `toHex` — Mermaid derives colors with khroma, so it needs plain hex, not `var()`/`color-mix()`; `renderMermaid` is serialized and idempotent: each block remembers its config key in `data-rm-config`, so `main.ts` calls it on config, scheme, and debounced `<html style>` (VS Code theme colors) changes and only changed diagrams redraw; SVG cache keyed by config + source), `mermaidZoom` (`decorateDiagrams` runs after every `renderMermaid`: hover toolbar `.rm-zoom` in the `.rm-mermaid` wrapper, CSS transform on the SVG with origin 0 0, `pre.rm-zoomed` clips; Ctrl/Cmd+wheel (= pinch) zooms around the pointer, drag pans only while zoomed so unzoomed diagrams keep selection/double-click edit, keys when the `pre` is focused; views kept in memory by source + occurrence, falling back to the same position when a diagram's source changed in place; full screen = fixed `.rm-diagram-full` overlay on `<body>` (webviews can't use the Fullscreen API) with a copy of the SVG whose id prefix is renamed (Mermaid prefixes all marker/style ids with the SVG id, duplicates would bind to the inline copy), fitted via the viewBox, re-copied by `decorateDiagrams` after each render), `settingsPanel` (quick ⚙ panel posting `updateSetting`; controls grouped in `SECTIONS`, one icon tab each (`role="tablist"`, arrow/Home/End keys); all `.rm-settings-panel`s share one grid cell so the pane keeps the tallest height, inactive ones `visibility: hidden` + `inert`; selected tab in `WebviewState.settingsTab`), `blockActions` (one floating hover rail per `[data-line-end]` block, edit mode only: `⋮⋮` handle opening a menu of `placement: 'menu'` actions, then `placement: 'rail'` buttons; ends left of a heading's `.rm-fold`. Features call `registerBlockAction` instead of adding their own gutter buttons — the handle is the intended drag grip), `editBlock` (registers the ✎ rail action, or double-click if `edit.doubleClick`, swaps a `[data-line-end]` block for a textarea; `deferRender` holds back `render` messages while it is open so they don't wipe it; task checkboxes are enabled and post `toggleTask`, which rewrites only the `[ ]`/`[x]` state char via `taskMarkerColumn`). Context menu: `main.ts` stamps `data-vscode-context` (`webviewSection: 'rm-block'`, `rmLine`) on each top-level block and `rmEditable` on `<body>`; `package.json` `webview/context` items run `readMarkdown.editBlock` (→ `startEdit` message) / `readMarkdown.showSource` with that object (`BlockMenuContext` in protocol). `sanitize` strips author-supplied `data-vscode-context`. `listDrag` (edit mode: floating ⠿ grip in a list's left padding; pointer drag lifts the `li` and translates siblings, or a drop line under `prefers-reduced-motion`; Alt+↑/↓ on the grip; reorders the DOM optimistically, then posts `moveListItem` with sibling `starts` + last `data-item-end`, and puts items back on a failed `moveResult`. List items carry `data-item-end` from the renderer; `edit/listMove.ts` (pure) moves the lines, keeping blank-line separators by position and renumbering ordered lists. `blockActions` ends a list's rail left of the grip via `itemGripLeft`). `changes` (runs after `sanitize`, before `buildSections`: tags added/modified/moved blocks `.rm-chg-*`, inline mode clones removed/moved-from blocks in from `originalHtml` with `data-line*`/`id` stripped, re-aligns list items / quoted blocks / table rows with `alignBlocks`, and wraps word diffs in `ins.rm-ins`/`del.rm-del` over text nodes; gutter mode only tags, plus `data-rm-del-before/after`). `changeGutter` (bar overlay in `#rm-main`, ResizeObserver-driven; move jump buttons, hover pairing via `data-move-id`, and an SVG connector per move pair in the left gutter, lanes assigned so overlapping moves don't share one; overview ruler = an SVG data URL set as the page's `::-webkit-scrollbar-track` background via `<style id="rm-change-ruler">` — fixed elements can't cover the native scrollbar, `html::` doesn't match it, so inner scrollbars are reset with `body *::-webkit-scrollbar-track`; relies on VS Code styling `::-webkit-scrollbar` in webviews; VS Code also sets standard `scrollbar-color` on `html`, which disables all `::-webkit-scrollbar*` rules, so the ruler style sets `html { scrollbar-color: auto }` and gives `body` VS Code's value back for inner scrollbars). `REMOVED_SELECTOR` clones are skipped by `sections`, `search`, `codeblocks`, task checkboxes and `listDrag` (not counted as items; hidden via `.rm-list-reordering` during a drag; a failed move restores the full child order). Toolbar ± / `readMarkdown.toggleChanges` flips inline↔gutter per panel (`WebviewState.changesMode`, reset when the setting changes). `taskProgress` (agent plan progress, `readMarkdown.tasks.agentProgress`: the renderer's `rm_task_active` rule turns `- [/]`/`[~]`/`[-]` items into unchecked items with `data-task="active"`, styled in CSS with a `label::after` "working" label so it is not DOM text; the module keys items by their own text across renders for the "just done" flash and follow-scroll (`WebviewState.followTasks`, `scrollProgrammatically` so the editor doesn't move), drives the `#rm-task-progress` bar and `nav.setTaskBadges` counts; `taskMarkerColumn`/`toggleTask` treat in-progress as unchecked). `tableResize` (drag a cell's right border to resize its column, double-click resets: first drag freezes all columns into an injected `colgroup.rm-colgroup` with `width` + `min-width` — `width` alone lets the anonymous inner table of the `display: block` table squeeze instead of scroll — plus `.rm-table-sized` (cells `overflow-wrap: anywhere`); no wrapper, the table stays the `[data-line-end]` block; hit-tests with `elementFromPoint` because pointer capture retargets the following click/dblclick to the table; capture-phase `pointerdown`/`dblclick` so block edit doesn't see border clicks; widths in `WebviewState.tableWidths` keyed by header text + occurrence, falling back to an unclaimed entry at the same table index with the same column count, which is re-keyed; skips `REMOVED_SELECTOR` clones and tables with author `<col>`s). `api.ts` wraps `acquireVsCodeApi` and `get/patchState` (scroll line + collapsed slugs persist across re-renders and reloads).

### Feedback-loop guards
Scroll sync is bidirectional; echo suppression uses timestamps (host: pure `sync/scrollEcho.ts` — `EditorScrollGuard` in the manager (echo window per editor after a reveal, plus the same-top-line check for multi-line edits) and an `EchoWindow` `previewEcho` on each panel, both `SCROLL_ECHO_MS`, injectable clock; webview: `isSuppressed()`/`scrollProgrammatically` in `webview/scroll.ts`). Keep these when touching scroll code. Highlight messages are deduped via `lastHighlightKey`.

### Caches and their invalidation
- Host: `render/highlightCache.ts` (pure) is an LRU around highlight.js keyed by language + code; anything else that affects the highlighted HTML must go into the key. `diffDocument` has a time budget (`DOCUMENT_DIFF_BUDGET_MS`; `AlignOptions.budgetMs`/`now`, injectable for tests): once spent, only exact matches and exact moves are reported. `alignBlocks` itself (webview) is unlimited by default.
- Track-changes baseline: `DocChanges.baselineId` (per-panel counter bumped when `originalRender` is replaced) identifies the rendered original. `BaselineSync` (`preview/baselineSync.ts`, pure; reset on `ready`/`reloadWebview`) sends `originalHtml` only when the webview lacks that id. `webview/baseline.ts` keeps one sanitized baseline, stored when the `render` message ARRIVES (before `deferRender` can replace it), released by a render without changes; an unknown id renders without change marks and posts `needBaseline` once per id, and the host re-sends with the HTML.
- Webview: `scroll.ts` `invalidate()` also runs `onInvalidate` listeners; `nav.ts` keeps heading positions (`activeHeading.ts`, binary search) and drops them there, so call `invalidate()` after anything that moves content. `scrollLine` is persisted through `debouncedSaver.ts` (flush before reading it from state). Collapsed state changes only through `sections.ts`, which notifies `onSectionsChange` (the fold-all button); do not toggle `rm-collapsed` elsewhere. A collapsed `.rm-section-body` carries `hidden="until-found"` (not `display: none`), so the find widget searches it and `beforematch` → `revealFound` expands the section; its content keeps layout boxes, so measuring code skips it with `isFolded(el)` (scroll map, outline positions, change gutter) instead of relying on empty rects. `searchIndex.ts` caches the flattened search text while a search is active; a MutationObserver drops it on child list, text and `SKIP_CLASSES` changes, so a new class in `SKIP` must be added to `SKIP_CLASSES`. `changeGutter.ts` builds its move-id map per update (`collectMovePairs`) and never keeps it across renders.

## Conventions
- Enum lists are `as const` arrays in `src/protocol.ts` (types derived from them). Defaults, enum lists and numeric ranges of every setting live once in the pure `src/config/values.ts`, which both `getSettings` (invalid value → default, out-of-range number → clamped) and `validateQuickSetting` use; `test/unit/settingsValues.test.ts` fails if they drift from `package.json`.
- New settings: add the default (and enum list / range) to `config/values.ts`; add to `package.json` `contributes.configuration`, `Settings`/`getSettings`, and if the webview needs it `UiConfig`/`toUiConfig`; quick-panel-editable ones also go in `QUICK_SETTING_KEYS` + `validateQuickSetting`. Update README settings table.
- Custom CSS hooks are public API (documented in README): `.rm-markdown`, `#rm-nav`, `.rm-section`, `.rm-heading`, `pre.rm-code`, `--rm-*` variables — don't rename casually.
- Keep `render/`, `diff/`, `config/styles.ts`, `sync/selection.ts` free of `vscode` imports so unit tests (`test/unit`) run under plain mocha.
